Update, Level 2 Build DONE 2026-11-05: the standalone C++ tool now carries vector add, tiled matmul, and stable softmax with a 16-test self-contained assertion runner (no external framework; Catch2 and GoogleTest were not fetched and nothing is vendored). A real debugging session is on file at level-2-build/DEBUG-SESSION.md: a tiled matmul variant missing its bounds guard produced a real AddressSanitizer heap-buffer-overflow WRITE at an edge size, and the fixed tool runs clean under ASan and UBSan (session is sanitizer-led; gdb is not installed on the build machine). GPU benchmarks on record are PyTorch native ops measured on the fleet GPU node (NVIDIA GeForce RTX 5050 Laptop GPU, compute capability 12.0, torch 2.11.0+cu128, CUDA events, median): vector add 381.3 GB/s, matmul 6764.67 GFLOP/s at 1024, softmax rows 848.71 GB/s; all 4 stored rows recompute within 1 percent. The custom CUDA harness level-2-build/cuda/kernels.cu is written but uncompiled and has never run: the GPU node has no CUDA toolkit in PATH or CUDA_PATH this cycle, torch reports CUDA_HOME None, and a Numba route failed on compute capability 12.0 support. Compiling and running it is the first Deep item. Build grade: 8,200 of 10,000, deductions named in level-2-build/README.md.

Update, Level 3 Deep DONE 2026-11-05 (compressed Deep, release v1.0): the profiler study ran on the fleet GPU node with torch.profiler op counts and CUDA-event timing over PyTorch routes only, every row labelled: matmul (native op) at 512, 1024, and 2048 (7642.29 GFLOP/s at 1024), softmax native fused op against an unfused manual sequence at three sizes (604.58 GB/s against 155.13 GB/s at 4096 by 1024, a factor of 3.9, with a per-stage profile: exp and div stages dominate the unfused cost), 9 rows verified by recomputation within 1 percent. torch.compile was attempted and failed on the Windows node by two recorded routes (TritonMissing in the committed run; Inductor needing a C compiler in an earlier probe), and CUPTI CUDA-activity rows were unavailable in the committed runs (CUPTI_ERROR_INVALID_DEVICE), so profiler evidence is op counts plus CUDA-event tables, recorded as such. The C++ Deep track evolved the tool with an atomics and memory-ordering example (counter exact at 1000000 under relaxed and seq_cst; producer-consumer handoff 200 of 200 under acquire-release, with the relaxed control also passing on x86 and named as no guarantee) and a move-semantics benchmark (LargeBuffer, 200000 doubles: 50 copies in 83.5614 ms, 50 moves in 3.52111 ms, counts exact). 15 new C++ tests pass (31 C++ total), 46 Python tests pass, and both tools run clean under ASan and UBSan with no new findings. The custom fused softmax kernel (level-3-deep/cuda/fused_softmax.cu) is written only, with its blocker analysis and expected profile argument in cuda/ANALYSIS.md: the node still has no CUDA toolkit, so it was not compiled or run, and compiling and running the custom kernels is v1.1 backlog item 1 in ROADMAP.md. Deep grade: 7,900 of 10,000, deductions named in level-3-deep/README.md (largest: custom kernel uncompiled, minus 1,000).
